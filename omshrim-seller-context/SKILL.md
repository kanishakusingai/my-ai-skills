# OMSHRIM seller context

Use OMSHRIM as the default brand, Amazon.in as the marketplace, INR for money, and Asia/Kolkata for dates and schedules. Follow the seller's current request when it changes a default. Carry established preferences between chats. Check current account figures for the task at hand and use approvals only within the task and scope they covered.

## Identify the right product

1. Start with the name, SKU, ASIN, photos or other details the seller provided. For an ambiguous name, consult the [product registry](references/products.md). Its dated entries give candidate identifiers and distinguishing features.
2. Verify the candidate against the seller's connected account. For example, “lamp” could refer to the rose lamp, the ocean wave cube or the Bluetooth speaker lamp. Compare the seller SKU and ASIN with the shape or controls visible in the photos. If more than one candidate still fits, ask about the detail that distinguishes them.
3. Read current listing or account data for specifications, price, stock, sales and financial figures. When asked to inspect a product, or when features determine keywords or content, examine every available gallery image. Keep competitor references separate from owned ASINs. A cancelled draft requires a fresh request to resume it.

## Apply the preferences relevant to the task

| Task | Seller preference |
| --- | --- |
| Keyword files | Deliver separate Exact and Phrase Excel files in the established layout. Use a newly supplied template when available, otherwise use the campaign designer's bundled template. |
| Keyword exclusions | Leave negative keywords out unless requested. If a search describes the wrong product, explain why it was excluded from the positive targets. |
| Launch planning | The seller has previously prioritised initial orders. When costs are missing, provide a clearly labelled test plan and mark profitability as unknown. State proposed budgets as recommendations until confirmed. |
| Bids | Earlier high-bid launches produced costly clicks. Choose a bid from current product relevance and performance evidence. A prior uplift or low bid applies only where the current evidence supports it. Avoid promising organic ranking gains. |
| Image edits | Change only the requested element. For a glow-only lamp edit, adjust the illumination and preserve the model, controls, surrounding layout and colour previews. |
| A+ content | Use clear, informative product visuals. Choose a carousel when its panels answer a buying question or explain a sequence. For a draft-only request, deliver the complete draft and stop there. |

Use the task-specific Amazon skill for the actual deliverable. Read relevant connected data before asking the seller for facts already available. Give a direct answer, concrete recommendations and accessible final files. Ask only for a consequential fact still missing. Carry forward authorisation already given for the current work and follow the connector's required approval flow for account changes.

## Maintain the context and its files

Keep reusable preferences in this brief and product identity references in the registry. Record a new lasting preference only when the seller's words support it. Date facts that can change. Resolve conflicts using current account evidence or a focused seller answer. Keep transcripts, tokens, passwords, bank numbers, buyer details, account financial totals and old approval IDs out of the skill.

Use the registry's asset-location notes to locate historical files. Check accessible locations and current permissions before asking for a missing source. Earlier permission to upload an asset was specific to that task.

When delivering or moving a skill, give the exact saved folder and report whether installation in a discovered skill directory was verified. A cloud backup establishes where a copy was stored. Verify that the skill is available to a new chat before claiming it will load there.
